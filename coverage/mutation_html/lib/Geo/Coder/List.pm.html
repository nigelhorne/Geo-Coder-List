  145: =head1 DESCRIPTION
  146: 
  147: L<Geo::Coder::All> and L<Geo::Coder::Many> are great modules but neither
  148: quite does what I want.
  149: 
  150: A I<geocoder> turns the name of a place, such as C<'Paris, France'>, into
  151: a position on the Earth (a latitude and a longitude).  There are many
  152: geocoding services.  Each one knows some places better than others, each
  153: one has its own limits, and each one returns its answer in its own format.
  154: 
  155: C<Geo::Coder::List> lets you use many geocoders as if they were one:
  156: 
  157: =over 4
  158: 
  159: =item * B<A chain.>
  160: You add geocoders with C<push()>.  When you ask for a place, the geocoders
  161: are asked one at a time, in the order you added them.  The first one that
  162: gives a usable answer wins, and the others are not asked.
  163: 
  164: =item * B<Routing.>
  165: A geocoder can be given a regular expression.  It is then asked only
  166: about places whose names match it.
  167: 
  168: =item * B<Limits.>
  169: A geocoder can be given a limit: the number of questions it may answer.
  170: When the limit is used up, the geocoder is skipped.
  171: 
  172: =item * B<One answer format.>
  173: Every answer is changed into the same structure, whichever service gave
  174: it.  The structure is the one used by L<HTML::GoogleMaps::V3> and
  175: L<HTML::OSM>:
  176: 
  177:     $result->{geometry}{location}{lat}   # latitude
  178:     $result->{geometry}{location}{lng}   # longitude
  179:     $result->{lat}                       # the same latitude, for convenience
  180:     $result->{lng}                       # the same longitude, for convenience
  181:     $result->{lon}                       # the same longitude, another common name
  182:     $result->{geocoder}                  # the geocoder object that answered,
  183:                                          # or the string 'cache'
  184: 
  185: =item * B<A cache in two levels.>
  186: Level 1 (L1) is a hash inside the object.  It is always used, and it lasts
  187: as long as the object.  Level 2 (L2) is optional.  It can be a plain hash
  188: or any object with C<get()> and C<set()> methods, such as a L<CHI> cache.
  189: L2 can last longer than the object and can be shared between programs.
  190: How long L2 keeps an answer depends on the answer:
  191: 
  192:     found                      1 month   (cache_hit_duration)
  193:     found, but no latitude     1 day     (cache_part_duration)
  194:     not found                  1 week    (cache_miss_duration)
  195: 
  196: A place that was not found is remembered in L1 only, never in L2.
  197: 
  198: =back
  199: 
  200: =head1 SUPPORTED ANSWER FORMATS
  201: 
  202: Each geocoding service answers in its own format.  C<geocode()> finds the
  203: latitude and longitude in each of the formats below and copies them into
  204: the common structure.  Any geocoder whose answers use one of these formats
  205: works without extra code.  The provider's own fields are kept as well.
  206: 
  207:     Service (module)                Where the position is found
  208:     ------------------------------  -----------------------------------------
  209:     OpenStreetMap, RandMcNally      lat, lon
  210:     Bing Maps                       BestLocation.Coordinates.Latitude/Longitude
  211:     Bing Maps (other form)          point.coordinates [lat, lng]
  212:     geocoder.ca (Geo::Coder::CA)    latt, longt
  213:     postcodes.io, Geo::Coder::Free  latitude, longitude
  214:     HERE / Ovi                      properties.geoLatitude/geoLongitude
  215:     DataScienceToolkit              results[0].geometry.location.lat/lng
  216:     OpenCage                        results[0].geometry.lat/lng
  217:     GeocodeFarm                     RESULTS[0].COORDINATES.latitude/longitude
  218:     US Census Bureau                result.addressMatches[0].coordinates.y/x
  219:     GeoNames                        lat, lng
  220:     Mapbox                          features[0].center [lng, lat]
  221:     GeoApify                        features[0].geometry.coordinates [lng, lat]
  222:     Google, and anything already    geometry.location.lat/lng
  223:     in the common structure
  224: 
  225: Notice that Mapbox and GeoApify give the longitude B<first>.
  226: 
  227: Some services need special handling, which is done for you:
  228: 
  229: =over 4
  230: 
  231: =item * B<Geo::Location::Point.>
  232: A geocoder may answer with a L<Geo::Location::Point> object.  Its
  233: C<geometry> is filled in from its own C<lat> and C<lng> (or C<lon>).
  234: 
  235: =item * B<postcodes.io.>
  236: Its C<local_type> field is copied to C<type>, with the first letter made
  237: lower case.
  238: 
  239: =item * B<geocoder.xyz.>
  240: Its C<standard.countryname> field is copied to C<address.country>.
  241: 
  242: =item * B<GeoNames.>
  243: L<Geo::GeoNames> is called with the place name alone, not with
  244: C<location =E<gt> ...>.  If it has no C<username>, it fails with
  245: C<lost username>, which is logged, and the next geocoder is asked.
  246: GeoNames puts its answers in arrays; every answer in them is considered.
  247: 
  248: =item * B<US Census Bureau.>
  249: An answer with no C<addressMatches> means "not found", and the next
  250: geocoder is asked.
  251: 
  252: =item * B<GeoApify.>
  253: An answer with an empty C<features> list means "not found", and the next
  254: geocoder is asked.
  255: 
  256: =item * B<Errors.>
  257: An answer with a top-level C<error> key is treated as a refusal, not as a
  258: place.  The error is logged, and the next geocoder is asked.
  259: 
  260: =back
  261: 
  262: Every answer that went through this process also has a C<debug> key.  It
  263: holds the line number, in this module, of the code that read the answer.
  264: It is there to help when a new format is not read correctly.

  400: =head2 push
  401: 
  402: Adds one geocoder to the end of the chain.  Geocoders are asked in the
  403: order in which they were added.
  404: 
  405: C<push> returns the object itself, so you can add several geocoders in
  406: one statement.
  407: 
  408: There are two ways to add a geocoder:
  409: 
  410: =over 4
  411: 
  412: =item * B<A geocoder object.>
  413: It is asked about every place.
  414: 
  415: =item * B<A hash reference>, with these keys:
  416: 
  417: =over 4
  418: 
  419: =item * C<geocoder> - Required.  The geocoder object.
  420: 
  421: =item * C<regex> - Optional.  A regular expression, made with C<qr//>.
  422: The geocoder is asked only about places whose names match it.
  423: 
  424: =item * C<limit> - Optional.  A whole number.  The geocoder answers at
  425: most this many questions.  Each question it is asked makes the number one
  426: smaller.  When the number reaches C<0>, the geocoder is skipped.  A place
  427: that does not match C<regex> does not use up the limit.
  428: 
  429: =back
  430: 
  431: =back
  432: 
  433:     my $list = Geo::Coder::List->new()
  434:         ->push({ regex => qr/USA$/, geocoder => Geo::Coder::US::Census->new(), limit => 100 })
  435:         ->push(Geo::Coder::OSM->new());

  502: =head2 geocode
  503: 
  504: Finds the position of a place from its name.
  505: 
  506:     my $result = $list->geocode(location => 'Paris, France');
  507:     my $result = $list->geocode('Paris, France');            # the same
  508:     my $result = $list->geocode({ location => 'Paris, France' });  # the same
  509: 
  510:     if($result) {
  511:         printf "lat=%.4f lng=%.4f from %s\n",
  512:             $result->{geometry}{location}{lat},
  513:             $result->{geometry}{location}{lng},
  514:             ref($result->{geocoder}) || $result->{geocoder};
  515:     }
  516: 
  517: These are the steps, in order:
  518: 
  519: =over 4
  520: 
  521: =item 1. If C<location> is missing, C<geocode> croaks.  If it is
  522: C<undef> or an empty string, C<geocode> warns and returns nothing.
  523: 
  524: =item 2. Runs of white space are made into one space, and HTML entities
  525: are decoded: C<'Caf&eacute;'> becomes C<'Caf'> followed by the single
  526: character e-acute.  A reference to a string is treated as the string.
  527: 
  528: =item 3. The text is checked.  A reference is never a place.  When
  529: L<Geo::Location::Predicate> is installed, it decides what else is not a
  530: place; for example, a string of only digits is not.  If the text is not a
  531: place, C<geocode> croaks.  The check is done after step 2, so
  532: C<'&#49;&#50;'> is refused as the digits C<'12'>.
  533: 
  534: =item 4. The cache is checked: first L1, then L2.  If the place is there,
  535: the cached answer is returned, with C<geocoder> set to C<'cache'>.  If L1
  536: remembers that the place was not found, nothing is returned and no
  537: geocoder is asked.
  538: 
  539: =item 5. Each geocoder in the chain is asked in turn.  A geocoder is
  540: skipped if the place does not match its C<regex>, or if its C<limit> is
  541: used up.  If a geocoder dies, the error is logged, a warning is given, and
  542: the next geocoder is asked.
  543: 
  544: =item 6. The first answer that has both a latitude and a longitude wins.
  545: It is changed into the common structure (see L</DESCRIPTION>), stored in
  546: the cache, and returned.
  547: 
  548: =item 7. If no geocoder gives a usable answer, the place is remembered as
  549: "not found" in L1, and nothing is returned.
  550: 
  551: =back
  552: 
  553: B<Scalar context> returns one hash reference, or C<undef>.
  554: 
  555: B<List context> returns every answer from the geocoder that won, or an
  556: empty list.  This is useful when a name, such as C<'Springfield'>, belongs
  557: to many places.  Answers that the geocoder returned inside an array are
  558: taken out of it, so the list never contains array references.  Answers
  559: without a position may be in the list too; check C<geometry> before you
  560: use each one.
  561: 
  562:     my @all = $list->geocode('Springfield, USA');
  563: 
  564: The C<geocoder> key of an answer holds the geocoder object that gave it.
  565: When the answer came from the cache, it holds the string C<'cache'>.

 1822: =head1 COMMON PITFALLS
 1823: 
 1824: =over 4
 1825: 
 1826: =item * B<Scalar context and list context give different answers.>
 1827: 
 1828: C<geocode()> and C<reverse_geocode()> return one answer in scalar
 1829: context and all answers in list context.  Perl decides the context from
 1830: the code around the call, and some places give list context when you may
 1831: not expect it:
 1832: 
 1833:     my %row = (name => $name, place => $list->geocode($name));  # list context!
 1834:     print 'Found: ', $list->geocode($name);                     # list context!
 1835:     return $list->geocode($name);                               # your caller decides
 1836: 
 1837: When nothing is found, list context returns an I<empty list>, so in the
 1838: first example the keys and values of C<%row> move out of step.  Use
 1839: C<scalar()> to be sure:
 1840: 
 1841:     my %row = (name => $name, place => scalar($list->geocode($name)));
 1842: 
 1843: =item * B<C<undef> means "not found" and also "bad empty input".>
 1844: 
 1845: C<geocode()> returns C<undef> both when no geocoder knows the place and
 1846: when C<location> is C<undef> or empty (it also warns in that case).  Other
 1847: bad input, such as a reference or a string of digits, does not return
 1848: C<undef>: it croaks.  Wrap the call in C<eval> when the text comes from
 1849: outside your program.
 1850: 
 1851: =item * B<"Not found" is remembered for the life of the object.>
 1852: 
 1853: When no geocoder finds a place, L1 remembers that, and later calls for
 1854: the same place return C<undef> at once without asking any geocoder, even
 1855: if a geocoder was only down for a moment.  C<flush()> does not forget it,
 1856: and nor does a clone, which shares L1.  Make a new object with
 1857: C<Geo::Coder::List-E<gt>new()> to ask again.  L2 never stores "not
 1858: found".
 1859: 
 1860: =item * B<An answer from L2 has only its position.>
 1861: 
 1862: To keep L2 small, only C<geometry> is stored there (unless C<debug> is
 1863: set).  An answer that comes from L2, for example in a new run of your
 1864: program, has C<geometry>, C<lat>, C<lng>, C<lon> and C<geocoder> (set to
 1865: C<'cache'>), but none of the provider's other fields, such as an address
 1866: or a place type.  Answers from L1 keep every field.
 1867: 
 1868: =item * B<The C<geocoder> key is not always an object.>
 1869: 
 1870: It is the geocoder object when a geocoder answered, and the string
 1871: C<'cache'> when the cache answered.  Do not call methods on it without
 1872: checking.  To get a printable name in both cases:
 1873: 
 1874:     my $source = ref($result->{geocoder}) || $result->{geocoder};
 1875: 
 1876: =item * B<Changing an answer changes the cache.>
 1877: 
 1878: The first answer for a place is the same hash that L1 stores.  If you
 1879: change it, later answers for that place, which are copies of the L1 entry,
 1880: include your change.  Copy the answer before you change it.
 1881: 
 1882: =item * B<The hash you give to C<push()> is changed.>
 1883: 
 1884: C<limit> counts down inside the hash reference that you pushed.  If you
 1885: push the same hash reference into two lists, they share one limit.  A
 1886: clone made with C<< $list->new() >> has its own copy.
 1887: 
 1888: =item * B<The cache key is the exact text.>
 1889: 
 1890: C<'Paris, France'>, C<'paris, france'> and C<'Paris,France'> are three
 1891: different keys, and each one asks the geocoders again.  Only runs of
 1892: white space are made into one space before the text is used as a key.
 1893: 
 1894: =item * B<HTML entities are always decoded.>
 1895: 
 1896: C<'AT&amp;T Park'> is looked up as C<'AT&T Park'>.  There is no way to
 1897: look up text that really contains C<&amp;>.
 1898: 
 1899: =item * B<Strings of digits depend on an optional module.>
 1900: 
 1901: When L<Geo::Location::Predicate> is installed, C<geocode('12345')> croaks.
 1902: When it is not installed, C<'12345'> is sent to the geocoders.  If you
 1903: handle postcodes or ZIP codes, add the country, such as
 1904: C<'12345, USA'>.
 1905: 
 1906: =item * B<C<reverse_geocode()> ignores C<regex>.>
 1907: 
 1908: A geocoder added with C<regex> is still asked to reverse geocode every
 1909: position.  Only C<limit> is honoured.
 1910: 
 1911: =item * B<The log grows until you empty it.>
 1912: 
 1913: Every call adds to the log.  In a long-running program, such as a web
 1914: server, call C<flush()> from time to time.
 1915: 
 1916: =item * B<Debug output goes to standard output.>
 1917: 
 1918: With C<debug> set, messages are printed to C<STDOUT>, not C<STDERR>, so
 1919: they mix with your program's own output.  The same messages are always
 1920: given to the configured C<logger> at debug level, whether C<debug> is set
 1921: or not, so a logger is the way to collect them somewhere else.
 1922: 
 1923: =back
 1924: 
 1925: =head1 ENCODING
 1926: 
 1927: =over 4
 1928: 
 1929: =item * B<Place names> (C<location> in C<geocode()>) may contain any
 1930: Unicode text, including accented letters, other alphabets and emoji.
 1931: Give them to C<geocode()> as Perl I<character> strings: if your text is
 1932: UTF-8 bytes from a file or a web form, decode it first, for example with
 1933: C<Encode::decode('UTF-8', $bytes)>.  HTML entities in the text are decoded
 1934: into characters, so text that mixes UTF-8 bytes that are not yet decoded
 1935: with entities becomes garbled.  The text is passed to each geocoder unchanged apart from
 1936: that; whether a geocoder understands emoji is up to the geocoder.
 1937: 
 1938: =item * B<White space.>  Runs of ASCII spaces, tabs and new lines are
 1939: always made into one space.  Unicode spaces, such as the no-break space,
 1940: may or may not be, depending on how Perl stores the string; do not rely on
 1941: it.
 1942: 
 1943: =item * B<Positions> (C<latlng> in C<reverse_geocode()>) must be ASCII.
 1944: Only the digits C<0> to C<9> are accepted.  Other Unicode digits, such as
 1945: Eastern Arabic or full-width digits, are refused.
 1946: 
 1947: =item * B<Cache keys> are the cleaned text, so they can contain any
 1948: character.  L1 and a plain-hash L2 accept them all.  An L2 object must
 1949: accept character-string keys; L<CHI> does.
 1950: 
 1951: =item * B<Answers> are returned as the geocoder gave them.  Most
 1952: geocoders return character strings.
 1953: 
 1954: =item * B<Debug output> prints place names to C<STDOUT>.  If they contain
 1955: characters above 255, Perl warns C<Wide character in print> unless
 1956: C<STDOUT> has an encoding layer, such as
 1957: C<binmode(STDOUT, ':encoding(UTF-8)')>.
 1958: 
 1959: =back
