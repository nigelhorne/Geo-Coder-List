   89: =head1 SYNOPSIS
   90: 
   91: L<Geo::Coder::All> and L<Geo::Coder::Many> are great modules but neither
   92: quite does what I want.
   93: 
   94: C<Geo::Coder::List> aggregates multiple geocoding services into a single,
   95: unified interface.  It chains and prioritizes backends based on regex routing
   96: and per-geocoder query limits, caches results at two levels (L1 in-memory
   97: always; optional L2 via CHI or a plain HASH), and normalizes every provider's
   98: idiosyncratic response into the common structure expected by
   99: L<HTML::GoogleMaps::V3> and L<HTML::OSM>:
  100: 
  101:     $result->{geometry}{location}{lat}   # canonical latitude
  102:     $result->{geometry}{location}{lng}   # canonical longitude
  103:     $result->{geocoder}                  # source object (or 'cache')
  104: 
  105:     use Geo::Coder::List;
  106:     use Geo::Coder::OSM;
  107:     use Geo::Coder::CA;
  108: 
  109:     my $list = Geo::Coder::List->new()
