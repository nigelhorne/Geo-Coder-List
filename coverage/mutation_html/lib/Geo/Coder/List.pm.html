  147: =head1 DESCRIPTION
  148: 
  149: L<Geo::Coder::All> and L<Geo::Coder::Many> are great modules but neither
  150: quite does what I want.
  151: 
  152: A I<geocoder> turns the name of a place, such as C<'Paris, France'>, into
  153: a position on the Earth (a latitude and a longitude).  There are many
  154: geocoding services.  Each one knows some places better than others, each
  155: one has its own limits, and each one returns its answer in its own format.
  156: 
  157: C<Geo::Coder::List> lets you use many geocoders as if they were one:
  158: 
  159: =over 4
  160: 
  161: =item * B<A chain.>
  162: You add geocoders with C<push()>.  When you ask for a place, the geocoders
  163: are asked one at a time, in the order you added them.  The first one that
  164: gives a usable answer wins, and the others are not asked.
  165: 
  166: =item * B<Routing.>
  167: A geocoder can be given a regular expression.  It is then asked only
  168: about places whose names match it.
  169: 
  170: =item * B<Limits.>
  171: A geocoder can be given a limit: the number of questions it may answer.
  172: When the limit is used up, the geocoder is skipped.

  175: Every answer is changed into the same structure, whichever service gave

 1751: C<geocode()> returns C<undef> both when no geocoder knows the place and
 1752: when C<location> is C<undef> or empty (it also warns in that case).  Other
 1753: bad input, such as a reference or a string of digits, does not return
 1754: C<undef>: it croaks.  Wrap the call in C<eval> when the text comes from
 1755: outside your program.
 1756: 
 1757: =item * B<"Not found" is remembered for the life of the object.>
 1758: 
 1759: When no geocoder finds a place, L1 remembers that, and later calls for
 1760: the same place return C<undef> at once without asking any geocoder, even
 1761: if a geocoder was only down for a moment.  C<flush()> does not forget it,
 1762: and nor does a clone, which shares L1.  Make a new object with
 1763: C<Geo::Coder::List-E<gt>new()> to ask again.  L2 never stores "not
 1764: found".
 1765: 
 1766: =item * B<An answer from L2 has only its position.>
 1767: 
 1768: To keep L2 small, only C<geometry> is stored there (unless C<debug> is
 1769: set).  An answer that comes from L2, for example in a new run of your
 1770: program, has C<geometry>, C<lat>, C<lng>, C<lon> and C<geocoder> (set to
 1771: C<'cache'>), but none of the provider's other fields, such as an address
 1772: or a place type.  Answers from L1 keep every field.
 1773: 
 1774: =item * B<The C<geocoder> key is not always an object.>
 1775: 
 1776: It is the geocoder object when a geocoder answered, and the string
 1777: C<'cache'> when the cache answered.  Do not call methods on it without
 1778: checking.  To get a printable name in both cases:
 1779: 
 1780:     my $source = ref($result->{geocoder}) || $result->{geocoder};
 1781: 
 1782: =item * B<Changing an answer changes the cache.>
 1783: 
 1784: The first answer for a place is the same hash that L1 stores.  If you
 1785: change it, later answers for that place, which are copies of the L1 entry,
 1786: include your change.  Copy the answer before you change it.
 1787: 
 1788: =item * B<The hash you give to C<push()> is changed.>
 1789: 
 1790: C<limit> counts down inside the hash reference that you pushed.  If you
 1791: push the same hash reference into two lists, they share one limit.  A
 1792: clone made with C<< $list->new() >> has its own copy.
 1793: 
 1794: =item * B<The cache key is the exact text.>
 1795: 
 1796: C<'Paris, France'>, C<'paris, france'> and C<'Paris,France'> are three
 1797: different keys, and each one asks the geocoders again.  Only runs of
 1798: white space are made into one space before the text is used as a key.
 1799: 
 1800: =item * B<HTML entities are always decoded.>
 1801: 
 1802: C<'AT&amp;T Park'> is looked up as C<'AT&T Park'>.  There is no way to
 1803: look up text that really contains C<&amp;>.
 1804: 
 1805: =item * B<Strings of digits depend on an optional module.>
 1806: 
 1807: When L<Geo::Location::Predicate> is installed, C<geocode('12345')> croaks.
 1808: When it is not installed, C<'12345'> is sent to the geocoders.  If you
 1809: handle postcodes or ZIP codes, add the country, such as
 1810: C<'12345, USA'>.
 1811: 
 1812: =item * B<C<reverse_geocode()> ignores C<regex>.>
 1813: 
 1814: A geocoder added with C<regex> is still asked to reverse geocode every
 1815: position.  Only C<limit> is honoured.
 1816: 
 1817: =item * B<The log grows until you empty it.>
 1818: 
 1819: Every call adds to the log.  In a long-running program, such as a web
 1820: server, call C<flush()> from time to time.
 1821: 
 1822: =item * B<Debug output goes to standard output.>
 1823: 
 1824: With C<debug> set, messages are printed to C<STDOUT>, not C<STDERR>, so
 1825: they mix with your program's own output.
 1826: 
 1827: =back
 1828: 
 1829: =head1 ENCODING
 1830: 
 1831: =over 4
 1832: 
 1833: =item * B<Place names> (C<location> in C<geocode()>) may contain any
 1834: Unicode text, including accented letters, other alphabets and emoji.
 1835: Give them to C<geocode()> as Perl I<character> strings: if your text is
 1836: UTF-8 bytes from a file or a web form, decode it first, for example with
 1837: C<Encode::decode('UTF-8', $bytes)>.  HTML entities in the text are decoded
 1838: into characters, so text that mixes UTF-8 bytes that are not yet decoded
 1839: with entities becomes garbled.  The text is passed to each geocoder unchanged apart from
 1840: that; whether a geocoder understands emoji is up to the geocoder.
 1841: 
 1842: =item * B<White space.>  Runs of ASCII spaces, tabs and new lines are
 1843: always made into one space.  Unicode spaces, such as the no-break space,
 1844: may or may not be, depending on how Perl stores the string; do not rely on
 1845: it.
 1846: 
 1847: =item * B<Positions> (C<latlng> in C<reverse_geocode()>) must be ASCII.
 1848: Only the digits C<0> to C<9> are accepted.  Other Unicode digits, such as
 1849: Eastern Arabic or full-width digits, are refused.
 1850: 
 1851: =item * B<Cache keys> are the cleaned text, so they can contain any
 1852: character.  L1 and a plain-hash L2 accept them all.  An L2 object must
 1853: accept character-string keys; L<CHI> does.
 1854: 
 1855: =item * B<Answers> are returned as the geocoder gave them.  Most
 1856: geocoders return character strings.
 1857: 
 1858: =item * B<Debug output> prints place names to C<STDOUT>.  If they contain
 1859: characters above 255, Perl warns C<Wide character in print> unless
 1860: C<STDOUT> has an encoding layer, such as
 1861: C<binmode(STDOUT, ':encoding(UTF-8)')>.
 1862:

 2103: =head1 STATE DIAGRAM
 2104: 
 2105: An object has three parts that change over time: its chain of geocoders,
 2106: its cache (one state for each place name), and its log.  Each part is
 2107: shown on its own below.
 2108: 
 2109: =head2 The object and its chain
 2110: 
 2111:     +-------------+  push($g)        +--------------+  push($g)
 2112:     |   EMPTY     |----------------->|    READY     |<-----------+
 2113:     | no geocoder |  adds $g to the  | 1+ geocoders |------------+
 2114:     +-------------+  end of chain    +--------------+  adds $g to the end
 2115:           |                                 |
 2116:           | geocode($t)                     | new() on the object
 2117:           | reverse_geocode($p)             | clone: copies the chain and
 2118:           v                                 | limits, shares L1 and L2,
 2119:     returns undef / ()                      | empties the log
 2120:     nothing is asked, but a                 v
 2121:     geocode() miss is still          +--------------+
 2122:     remembered in L1                 | READY (clone)|
 2123:                                      +--------------+
 2124: 
 2125: =head2 The cache, for one place name $t
 2126: 
 2127:     +-----------+ geocode($t): a geocoder gives a usable answer
 2128:     |           |----------------------------------------------+
 2129:     |  UNKNOWN  |  - answer stored in L1                       |
 2130:     | not in L1 |  - copy with only geometry stored in L2,     |
 2131:     |           |    kept for cache_hit_duration (1 month)     |
 2132:     +-----------+  - log gets one entry per geocoder asked     |
 2133:        |  ^                                                    v
 2134:        |  |                                             +-----------+
 2135:        |  | L2 entry expires, and a new object          |  FOUND    |<--+
 2136:        |  | is used (L1 dies with its object)           |  L1 holds |   | geocode($t):
 2137:        |  +---------------------------------------------| an answer |---+ no geocoder
 2138:        |                                                +-----------+   asked; a copy
 2139:        | geocode($t): no geocoder gives a usable answer                 returned with
 2140:        |  - L1 stores "not found"; L2 is not written                    geocoder='cache';
 2141:        |  - log gets one entry per geocoder asked                       log gets one
 2142:        v                                                                cache entry
 2143:     +-----------+
 2144:     | NOT FOUND |<--+ geocode($t): nothing asked, undef / () returned,
 2145:     | in L1     |---+ nothing logged
 2146:     +-----------+
 2147:           |
 2148:           +-- leaves this state only when the object is destroyed;
 2149:               flush() and clones do not leave it
 2150: 
 2151:     Any state: geocode($t) with a reference, digits (when
 2152:     Geo::Location::Predicate is installed) or entity-encoded digits
 2153:     --> croaks; the state does not change.
 2154: 
 2155: =head2 The limit of one geocoder pushed with limit => N
 2156: 
 2157:     +--------------+ geocode($t), $t matches regex   +--------------+
 2158:     |  ACTIVE      |-------------------------------->|  ACTIVE      |
 2159:     |  limit = n   |  geocoder asked; limit = n - 1  |  limit = n-1 |
 2160:     +--------------+                                 +--------------+
 2161:        |      ^                                             |
 2162:        |      | geocode($t), $t does not match regex:       | ... when the
 2163:        |      | geocoder not asked, limit unchanged         | limit reaches 0
 2164:        +------+                                             v
 2165:                                                      +--------------+
 2166:                                                      |  EXHAUSTED   |<--+
 2167:                                                      |  limit <= 0  |---+
 2168:                                                      +--------------+ geocode() and
 2169:                                                                       reverse_geocode():
 2170:                                                                       skipped, never asked
